## Description

The offline `state-summary` command validates job statuses but currently accepts
duplicate job IDs. A duplicated durable identity makes the aggregate misleading
because one logical job can be counted more than once.

Require job IDs to be non-empty strings and unique before counting statuses.
Preserve the existing summary shape, ordering, privacy boundary, and all other
command behavior.

## Acceptance criteria

1. A structurally otherwise-valid state containing duplicate job IDs exits `1`,
   writes empty stdout, and writes exactly
   `state-summary: state file has invalid Relay state\n` to stderr.
2. Duplicate detection covers duplicates across any job statuses and completes
   before counting or output.
3. A job with a missing, empty, or non-string ID produces the same fixed,
   redacted invalid-state failure.
4. Failures do not print a job ID, event ID, error, input path, or state content
   and leave the state file and sibling paths unchanged.
5. Existing valid and empty summaries remain byte-for-byte unchanged,
   deterministic, offline, read-only, and self-terminating. Existing argument,
   read, JSON-parse, and unrelated structural failures retain their current
   exact exit codes and messages.
6. Tests precede implementation. The targeted test, full app suite, and
   immutability check pass without server, dependency, persisted-schema,
   Factory, or other tool changes.
