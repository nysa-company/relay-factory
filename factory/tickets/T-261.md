## Description

Relay currently treats a missing state file and an existing state file that
cannot be read or parsed as the same first-boot condition. Starting with empty
memory after persisted state becomes unreadable can hide durable work and allow
a later write to replace the last known state.

Make startup fail closed when `state.json` exists but is unreadable or is not
valid JSON. A genuinely absent `state.json` remains the supported first-boot
case. Keep the persisted schema, normal startup, worker behavior, routes, and
successful recovery unchanged.

## Acceptance criteria

1. Starting Relay with an existing malformed `state.json` exits `1` before
   opening a listener or starting the worker, writes zero stdout bytes, and
   writes exactly `relay: persisted state is unreadable or invalid\n` to stderr.
2. Starting Relay when `state.json` is a directory produces the same fixed,
   redacted failure. Neither failure exposes a path, operating-system detail,
   parser detail, or persisted content.
3. Each refused startup leaves the state artifact, its bytes where applicable,
   and every sibling directory entry unchanged. It creates no temporary state
   file.
4. An absent `state.json` remains a valid first boot. Existing valid-state
   restart and crash-recovery behavior remains green.
5. The targeted test is deterministic, offline, zero-dependency, and proves
   that each invalid-state process terminates on its own without requiring a
   signal or timeout kill.
6. Tests precede implementation. The targeted test, full app suite, and
   immutability check pass without Factory, dependency, schema, route, or
   configuration changes.
