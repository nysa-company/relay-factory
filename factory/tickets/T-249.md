## Description

Add a zero-dependency, read-only Node command that counts persisted Relay
events whose type and received timestamp exactly match supplied strings. This
supports narrow offline event checks without starting Relay or exposing event
payloads.

## Acceptance criteria

1. `node app/tools/event-type-received-count.js <state-file> <event-type> <received-at>`
   emits compact JSON containing exactly one `eventsWithTypeAndReceivedAt`
   integer.
2. Event type and received timestamp must be non-empty strings and match stored
   `type` and `receivedAt` values exactly, without trimming, timestamp parsing,
   normalization, or coercion.
3. Invalid arguments are rejected before file access. Unreadable, malformed,
   or structurally invalid state returns fixed redacted errors; complete event
   validation precedes counting.
4. Every invocation is offline, read-only, deterministic, and self-terminating.
5. Tests precede implementation. Targeted, full app, and immutability checks
   pass without dependency, server, schema, manifest, or Factory changes.

### Files

### CLI interface

```
node app/tools/event-type-received-count.js <state-file> <event-type> <received-at>
```

- Exactly 3 positional arguments are required. 0, 1, 2, or 4+ arguments is an
  arity error.
- Arity error (checked before any file access):
  - stdout: empty (0 bytes)
  - stderr: exactly
    `usage: node app/tools/event-type-received-count.js <state-file> <event-type> <received-at>\n`
  - exit code: `2`

### State-file loading and validation (in this exact order)

1. Read `<state-file>` with `readFileSync(path, "utf8")`.
   - On any read failure (absent path, directory path, permission error):
     - stdout: empty
     - stderr: exactly `event-type-received-count: cannot read state file\n`
     - exit code: `1`
2. `JSON.parse` the contents.
   - On parse failure:
     - stdout: empty
     - stderr: exactly `event-type-received-count: state file is not valid JSON\n`
     - exit code: `1`
3. Validate structure (mirrors `app/tools/event-type-count.js` /
   `app/tools/event-timestamp.js` `isValidState`):
   - Parsed value is a non-null, non-array object.
   - It has own properties `events`, `jobs`, `approvals`, `outbox`, each an
     `Array`.
   - Every element of `events` is a non-null, non-array object with own
     string properties `id`, `type`, `receivedAt`, each a non-empty string
     (`Object.hasOwn` + `typeof === "string"` + `length > 0`).
   - No two elements of `events` share the same `id` value.
   - `jobs`, `approvals`, `outbox` element contents are NOT validated (opaque
     — may contain non-object, `null`, or arbitrary-shaped entries; only their
     own-property values must be an `Array`).
   - On any structural-validation failure:
     - stdout: empty
     - stderr: exactly `event-type-received-count: invalid Relay state\n`
     - exit code: `1`

### Argument validation for `<event-type>` and `<received-at>`

- Both are always non-empty strings by construction of `process.argv` — no
  additional CLI-argument-shape rejection exists beyond the arity check above
  (this mirrors `event-type-count.js` and `event-timestamp.js`, neither of
  which imposes extra shape checks on its string arguments beyond arity).
- Matching against stored `event.type` and `event.receivedAt` is exact
  (`===`), case-sensitive, byte-for-byte. No trimming, no timestamp parsing,
  no normalization, no coercion in either direction.

### Success output

- Count = number of elements of `state.events` where
  `event.type === <event-type>` AND `event.receivedAt === <received-at>`
  (both conditions on the same event).
- stdout: exactly one line,
  `` `${JSON.stringify({ eventsWithTypeAndReceivedAt: <count> })}\n` `` —
  i.e. compact JSON `{"eventsWithTypeAndReceivedAt":<integer>}` followed by
  `\n`. No other stdout output.
- stderr: empty (0 bytes).
- exit code: `0`.
- A count of `0` is success (exit 0), never treated as a "not found" error.

### Non-functional constraints (mirrors `event-type-count.js` / `event-timestamp.js` AC8)

- `app/tools/event-type-received-count.js` requires only `node:fs`, and only
  the `readFileSync` export from it.
- `app/tools/event-type-received-count.js` must not reference: `server.js`,
  `fetch(`, `WebSocket`, `node:http`, `node:https`, `node:net`,
  `node:child_process`, `setTimeout`, `setInterval`.
- Every invocation is synchronous, deterministic, self-terminating (process
  exits on its own without any timer/socket keeping the event loop alive),
  and never mutates the state file or its parent directory (verified via
  byte + `fs.statSync(..., {bigint:true})` snapshot equality and
  `readdirSync` parent-entry equality before/after each invocation).
- `app/tests/event-type-received-count.test.js` requires only
  `node:assert`, `node:child_process`, `node:fs`, `node:os`, `node:path`,
  `node:test`.

    `action.to`, `action.subject`, `action.body`, `reason`, `to`, `subject`,

  on an empty `events` array succeeds with count `0` (not an error).
- **Fixture C** — truncated/malformed JSON (parse failure case), containing a
  `MALFORMED-...-MUST-NOT-LEAK` token that must never be echoed.
- **Fixture D** — zero-byte file (parse failure case).
- **Structural-invalid fixtures S1–S_N** — at minimum, one fixture per

  a `<received-at>` argument that differs from a stored `receivedAt` only in
  case/whitespace/trailing-zero formatting) yields count `0`, not a match —
  proving no normalization/trimming occurs.
- All fixtures above must be pairwise byte-distinct; the test must assert
  this distinctness explicitly (mirrors `assertPairwiseDistinct` /

### Acceptance criteria

1. Given Fixture A, invoking the tool twice in a row with a `<event-type>`
   and `<received-at>` pair that matches exactly one stored event prints
   `{"eventsWithTypeAndReceivedAt":1}\n` on stdout, empty stderr, exit code
   `0`, on both invocations, and leaves the fixture file's bytes and
   `fs.statSync(..., {bigint:true})` fields (`mode`, `size`, `mtimeNs`)
   unchanged, and leaves the parent directory's entry list unchanged.
2. Given Fixture A, invoking the tool with a `<event-type>`/`<received-at>`
   pair matching zero stored events (including the case where `<event-type>`
   matches a stored type but `<received-at>` does not, and vice versa) prints
   `{"eventsWithTypeAndReceivedAt":0}\n` on stdout, empty stderr, exit code
   `0` — a zero match is success, never a "not found" error.
3. Given Fixture A, a `<event-type>` argument that is byte-identical to a
   stored `type` except for letter case, or a `<received-at>` argument that
   is byte-identical to a stored `receivedAt` except for case/whitespace,
   both yield `{"eventsWithTypeAndReceivedAt":0}\n` — proving exact,
   case-sensitive, non-normalized matching with no trimming or timestamp
   parsing.
4. Given Fixture B (`events: []`), any `<event-type>`/`<received-at>` pair
   prints `{"eventsWithTypeAndReceivedAt":0}\n` with exit code `0` (not an
   error), proving an empty `events` array is valid state.
5. Invoking the tool with 0, 1, 2, or 4 positional arguments prints nothing
   to stdout, prints exactly
   `usage: node app/tools/event-type-received-count.js <state-file> <event-type> <received-at>\n`
   to stderr, exits `2`, and never creates, reads, or touches any candidate
   state-file path (the candidate path must not exist afterward, and its
   parent directory's entries must be unchanged).
6. An absent state-file path and a directory path (in place of a file) both
   print nothing to stdout, print exactly
   `event-type-received-count: cannot read state file\n` to stderr, exit `1`,
   and leave the filesystem unchanged (absent path stays absent; directory
   path's `fs.statSync(..., {bigint:true})` fields and entry list are
   unchanged).
7. Fixtures C (truncated JSON) and D (zero-byte file) both print nothing to
   stdout, print exactly
   `event-type-received-count: state file is not valid JSON\n` to stderr,
   exit `1`, never echo any fixture bytes (including the
   `MALFORMED-...-MUST-NOT-LEAK` token) into stdout or stderr, and leave the
   fixture file unchanged.
8. Every structural-invalid fixture (S1 through S_N, covering: non-object
   root, array root, a missing required collection key, a non-array
   collection value, a null/array/non-object `events` element, an `events`
   element missing `id`/`type`/`receivedAt`, an `events` element with an
   empty-string or non-string `id`/`type`/`receivedAt`, and duplicate `id`
   values across two `events` elements) prints nothing to stdout, prints
   exactly `event-type-received-count: invalid Relay state\n` to stderr,
   exits `1`, and leaves the fixture file unchanged. The test proves all
   fixtures (A, B, C, D, S1..S_N) are pairwise byte-distinct before running
   this check.
9. No sensitive fixture token (any string ending in `-MUST-NOT-LEAK` present
   anywhere in Fixture A's `jobs`, `approvals`, `outbox`, `metadata`, or any
   `events[].payload`) ever appears in stdout or stderr on any invocation in
   any acceptance test, across all exit-code paths (0, 1, 2).
10. `app/tools/event-type-received-count.js` exists, its `require(...)`
    module-specifier set is exactly `["node:fs"]`, its destructured
    `node:fs` usage is exactly `["readFileSync"]`, and its source contains
