## Description

The offline approval commands (`app/tools/blocked-approvals.js`,
`app/tools/pending-approvals.js`) validate approval fields but currently
accept duplicate approval IDs. A duplicated durable identity makes the safety
queues ambiguous and can produce apparently authoritative rows for one
approval (SPEC.md: approvals are the durable gate between a proposed action
and its execution — §"Proposed action requiring approval before execution").

Require approval IDs to be unique across the entire `state.approvals` array
(all statuses) before either command filters or reports. On a duplicate,
treat the state exactly as the existing "invalid Relay state" case: reuse
each command's existing, unchanged `INVALID_STATE` stderr line verbatim, exit
`1`, and write nothing to stdout. Preserve the existing report shapes,
sorting, privacy boundaries, and all other command behavior.

### Implementation contract (Builder ownership: `app/tools/blocked-approvals.js`, `app/tools/pending-approvals.js` only)

In each file, replace the `isValidState` function with the following
(identical shape in both files; only the file's own `APPROVAL_STATUSES` set
and constants stay as they already are — do not add any `require`):

```js
function isValidState(state) {
  if (state === null || typeof state !== "object" || Array.isArray(state)) {
    return false;
  }

  for (const collection of ["events", "jobs", "approvals", "outbox"]) {
    if (
      !Object.prototype.hasOwnProperty.call(state, collection) ||
      !Array.isArray(state[collection])
    ) {
      return false;
    }
  }

  const structurallyValid = state.approvals.every(approval =>
    approval !== null &&
    typeof approval === "object" &&
    !Array.isArray(approval) &&
    typeof approval.id === "string" &&
    approval.id.length > 0 &&
    typeof approval.jobId === "string" &&
    approval.jobId.length > 0 &&
    typeof approval.proposedAt === "string" &&
    approval.proposedAt.length > 0 &&
    typeof approval.status === "string" &&
    APPROVAL_STATUSES.has(approval.status)
  );

  if (!structurallyValid) {
    return false;
  }

  const seenIds = new Set();
  for (const approval of state.approvals) {
    if (seenIds.has(approval.id)) {
      return false;
    }
    seenIds.add(approval.id);
  }

  return true;
}
```

`main()` and every existing constant (`USAGE`, `CANNOT_READ`, `NOT_JSON`,
`INVALID_STATE`, `APPROVAL_STATUSES`) are unchanged. No new `require`, no new
file, no change to the filter/map/sort/output pipeline.
