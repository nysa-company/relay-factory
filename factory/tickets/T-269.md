## Description

Relay persists a truthy numeric event `type` unchanged, but the existing
offline `event-metadata` command rejects that state before exact-ID lookup.
The command already serializes the selected stored type safely as JSON.

Make exact event inspection accept persisted non-zero JSON-number types and
emit the selected number unchanged. Preserve exact lookup, key order, string
types, structural checks, failure behavior, privacy, and read-only operation.

## Acceptance criteria

1. Looking up valid events whose stored `type` values are numeric `7` and
   `-0.5` exits `0` for each, writes exactly one compact JSON line whose keys
   remain `eventId`, `type`, and `receivedAt` in that order and whose `type`
   value is the unchanged JSON number, and writes zero stderr bytes.
2. Existing valid string-type lookups remain byte-for-byte unchanged. Exact,
   case-sensitive event-ID lookup and not-found behavior remain unchanged.
3. Missing or empty types, zero, booleans, objects, arrays, invalid IDs or
   timestamps, and duplicate event IDs retain the existing invalid-state
   failure before lookup.
4. Output never adds payloads or unrelated event, job, approval, or outbox
   fields. Failures retain the existing fixed redacted one-line envelopes and
   leak none of those fields or the requested ID or path.
5. The command remains deterministic, offline, zero-dependency, read-only,
   and self-terminating. It changes no input bytes, metadata, or sibling path.
6. Tests precede implementation. The targeted test, full app suite, and
   immutability check pass without server, schema, package, dependency,
   Factory, route, or configuration changes.
