## Spec'd description

Add `app/tools/approval-recipient-subject-count.js`, a zero-dependency
CommonJS command that reads one persisted Relay state file while Relay is
offline, validates the complete stored approval collection, and counts
approvals whose stored `action.to` and `action.subject` are both strictly equal
to two operator-supplied strings. It emits only
`{"approvalsWithRecipientAndSubject":<count>}`, allowing an operator to answer
the conjunction query without starting Relay, changing durable state, or
exposing either query, action content, approval identity, job link, status,
reason, timestamp, sibling collection content, or other stored data.

### Command-line interface and failure precedence

- Invocation is exactly
  `node app/tools/approval-recipient-subject-count.js <state-file> <recipient> <subject>`.
- Exactly three user arguments are accepted. Any other arity exits `2`, writes
  zero stdout, writes exactly the following LF-terminated stderr line, and
  does not access a candidate path:

  ```text
  usage: node app/tools/approval-recipient-subject-count.js <state-file> <recipient> <subject>
  ```

- The command then synchronously reads the path as UTF-8. Any `readFileSync`
  failure exits `1`, writes zero stdout, and writes exactly:

  ```text
  approval-recipient-subject-count: cannot read state file
  ```

- Bytes rejected by `JSON.parse` exit `1`, write zero stdout, and write:

  ```text
  approval-recipient-subject-count: state file is not valid JSON
  ```

- Parsed values rejected by the structural rules exit `1`, write zero stdout,
  and write:

  ```text
  approval-recipient-subject-count: invalid Relay state
  ```

- Precedence is arity, read, parse, complete structural validation, counting.
  Each error is exactly one LF-terminated line and contains no supplied path,
  recipient, subject, OS/parser text, input bytes, stack, stored field, or
  second line. Absolute temporary paths are used. Symlinks and portable OS
  permission-denial simulation are outside the required matrix; if reading
  either throws, the frozen read-error result applies.

### Valid state, matching, and output

A valid state is a non-null, non-array JSON object with own array properties
`events`, `jobs`, `approvals`, and `outbox`. Extra top-level properties are
ignored. Every approval is a non-null, non-array object with:

- non-empty string own `id`, `jobId`, and `proposedAt`;
- own `status` equal to `pending`, `sent`, `rejected`, or
  `blocked_recipient`;
- own non-null, non-array `action` with own `to`, `subject`, and `body`; and
- absent own `reason`, or own `reason` equal to `null` or any string.

Approval IDs are pairwise distinct. Action values are opaque; extra action and
approval properties are ignored. Event, job, and outbox elements are opaque.
Job links need not resolve, timestamps need not parse, and no cross-field
relationship is imposed.

The complete approval array and ID uniqueness are validated before counting.
An approval contributes one only when both
`approval.action.to === <recipient>` and
`approval.action.subject === <subject>`. Equality is case-sensitive and does
not coerce, trim, case-fold, decode, or normalize Unicode. CLI arguments are
strings, so non-string stored values cannot match. Empty strings are accepted
arguments; no match is success, not an error.

Success exits `0`, writes zero stderr, and writes one compact object plus one
LF with exactly this key:

```json
{"approvalsWithRecipientAndSubject":<nonnegative integer>}
```

No query or stored value is emitted.
