## Spec'd description

Add `app/tools/event-timestamp-count.js`, a zero-dependency CommonJS command
that reads one persisted Relay state file while Relay is offline, validates
the complete stored event collection, and counts events whose stored
`receivedAt` string is strictly equal to one operator-supplied `<timestamp>`.
It reports only `{"eventsAtTimestamp":<count>}`, allowing an operator to
inspect timestamp cardinality without starting Relay, changing durable state,
parsing or converting timestamps, or exposing the supplied timestamp, event
IDs, types, payloads, stored timestamps, job details, approval details, outbox
details, or unrelated metadata.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/event-timestamp-count.js <state-file> <timestamp>`.
- Exactly two user-supplied positional arguments are accepted. Any other
  arity exits `2`, writes zero stdout bytes, writes exactly the following
  single LF-terminated line to stderr, and does not read or create a candidate
  state path:

  ```text
  usage: node app/tools/event-timestamp-count.js <state-file> <timestamp>
  ```

- After arity validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure, including an absent path, a
  directory in place of a regular file, or an OS read denial, exits `1`,
  writes zero stdout bytes, and writes exactly:

  ```text
  event-timestamp-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  event-timestamp-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  event-timestamp-count: invalid Relay state
  ```

- Failure precedence is argument count, file read, JSON parse, complete
  structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes
  the state path, supplied timestamp, OS error, parser text, input bytes, stack
  trace, event field, job field, approval field, outbox field, or second line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable
  simulation of OS permission denial are outside the required fixture matrix;
  if `readFileSync` throws for either, the frozen read-error result applies.

### Structurally valid state, exact match, and successful output

A structurally valid state for this command is a parsed non-null, non-array
JSON object with own `events`, `jobs`, `approvals`, and `outbox` properties
whose values are arrays. Additional top-level properties are allowed and
ignored.

Every `events` element must be a non-null, non-array object with non-empty
string own properties `id` and `receivedAt`. Event IDs must be pairwise
distinct across the complete array. Event `type`, `payload`, and all
additional event fields are opaque. Job, approval, and outbox elements are
wholly opaque; only the fact that their top-level collections are arrays is
validated. Stored `receivedAt` values need not be distinct and are not
required to parse as dates.

The command validates the complete event array and event-ID uniqueness before
counting. An event contributes one only when its stored `receivedAt` is
strictly equal to the supplied `<timestamp>` using case-sensitive JavaScript
string equality. Neither value is trimmed, parsed as a date, case-folded,
decoded, coerced, prefixed, normalized, reformatted, or timezone-converted.
The empty string is an accepted positional argument but cannot equal any
structurally valid non-empty stored `receivedAt`. A supplied timestamp with no
match is a successful query with count zero; there is no not-found error.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key is:

```json
{"eventsAtTimestamp":<nonnegative integer count>}
```

`eventsAtTimestamp` is the number of elements in the validated `events` array
whose stored `receivedAt` matches the supplied timestamp exactly. The supplied
timestamp is not echoed. No stored event ID, type, payload, `receivedAt`,
additional event field, job, approval, outbox, or metadata value is emitted.

   no trimming, parsing, coercion, normalization, formatting, or timezone

   parsing and trimming observable.

   requires every exact no-match to return zero and describes stored and
