## Spec'd description

Add `app/tools/outbox-approval-recipient-count.js`, a zero-dependency CommonJS
command that reads one persisted Relay state file while Relay is offline,
validates the complete sandbox-outbox collection, and counts receipts whose
stored `approvalId` and stored `to` are both strictly equal to the two supplied
non-empty strings. It reports only
`{"outboxWithApprovalAndRecipient":<count>}`, allowing a narrow conjunction
check without starting Relay, changing state, looking up or echoing a receipt,
creating a sandbox send, performing an external send, or exposing supplied or
stored receipt content.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/outbox-approval-recipient-count.js <state-file> <approval-id> <recipient>`.
- Exactly three user-supplied positional arguments are required, and both
  filter arguments must have a string length greater than zero. Wrong arity,
  an empty `<approval-id>`, or an empty `<recipient>` exits `2`, writes zero
  stdout bytes, writes exactly the following LF-terminated line to stderr, and
  does not read or create the candidate state path:

  ```text
  usage: node app/tools/outbox-approval-recipient-count.js <state-file> <approval-id> <recipient>
  ```

- After argument validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure exits `1`, writes zero stdout
  bytes, and writes exactly:

  ```text
  outbox-approval-recipient-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  outbox-approval-recipient-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  outbox-approval-recipient-count: invalid Relay state
  ```

- Failure precedence is argument count and non-empty filters, file read, JSON
  parse, complete structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes
  a state path, supplied filter, OS error, parser text, input bytes, stack
  trace, stored field, event, job, approval, metadata value, or second line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable OS
  permission-denial simulation are outside the fixture matrix; any thrown
  `readFileSync` error receives the frozen read-error envelope. The directory
  case freezes the command result, not a platform-specific errno.

### Structurally valid state, exact conjunction, and success

A structurally valid state is a parsed non-null, non-array JSON object with own
`events`, `jobs`, `approvals`, and `outbox` properties whose values are arrays.
Additional top-level properties are allowed and ignored.

Every `outbox` element must be a non-null, non-array object with:

- own `to`, `subject`, and `body` properties, whose values are opaque;
- a non-empty string own `approvalId` property; and
- a non-empty string own `sentAt` property.

Outbox `approvalId` values must be pairwise distinct across the complete
array. Additional outbox properties are allowed and ignored. Event, job, and
approval elements are wholly opaque; only their containing arrays are
validated. An outbox approval ID need not resolve to a stored approval. No
relationship is imposed among receipt fields beyond the individual rules.

The command validates the complete outbox array and approval-ID uniqueness
before counting. A receipt contributes one only when both
`receipt.approvalId === approvalId` and `receipt.to === recipient` using
case-sensitive JavaScript strict equality. Values are not trimmed, case-folded,
decoded, parsed, stringified, prefixed, or normalized. Because command-line
filters are non-empty strings, an opaque non-string stored `to` cannot match.
An unmatched filter pair is a successful zero-count query.

Pairwise-distinct approval IDs limit successful counts to `0` or `1`. Success
exits `0`, writes zero stderr bytes, and writes one compact JSON object followed
by exactly one LF. Its only key is:

```json
{"outboxWithApprovalAndRecipient":<0-or-1>}
```

No supplied filter or stored content is emitted.
