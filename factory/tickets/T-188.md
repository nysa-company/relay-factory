## Spec'd description

Add `app/tools/job-link.js`, a zero-dependency Node 18+ command that reads one
persisted Relay state file without starting the service, selects one job by
case-sensitive exact stored ID, and writes only that job's stored `id`,
`eventId`, and `status` under the keys `jobId`, `eventId`, and `status`. The
command validates the complete event/job relationship before lookup, so it
does not report a confident link from corrupt or ambiguous state. It never
prints event payloads, job errors, approval actions or reasons, outbox message
content, or unrelated state.

This gives an operator a deterministic offline job-to-event link check while
preserving Relay's state and process boundaries. It adds no endpoint, server
behavior, UI, schema, worker behavior, package, dependency, lockfile,
authentication path, deployment topology, external send, or Factory-control
change.

### Command interface and output

- Repository-root invocation is exactly
  `node app/tools/job-link.js <state-file> <job-id>`.
- Exactly two positional arguments after the script path are accepted. Any
  other arity exits `2`, writes zero bytes to stdout, writes exactly
  `usage: node app/tools/job-link.js <state-file> <job-id>\n` to stderr, and
  performs no state-file read.
- After arity validation, the command synchronously reads `<state-file>` as
  UTF-8, parses and validates it in memory, selects the job whose stored `id`
  is strictly equal to `<job-id>`, writes its result, and exits.
- Lookup is exact, case-sensitive JavaScript string equality. The command does
  not trim, normalize, decode, case-fold, prefix-match, or substring-match
  either value.
- Success exits `0`, writes zero stderr bytes, and writes one compact JSON
  object followed by exactly one LF. Its only keys, in order, are `jobId`,
  `eventId`, and `status`. Each value copies the selected job's stored `id`,
  `eventId`, or `status` without transformation.
- The exact success shape is
  `{"jobId":<stored nonempty string>,"eventId":<stored nonempty string>,"status":<"pending"|"done"|"dead">}\n`.
- A link-valid state with no exact job match exits `1`, writes zero bytes to
  stdout, and writes exactly `job-link: job not found\n` to stderr. The error
  never echoes the supplied ID.
- The command does not import or start `app/server.js`, open a socket, issue a
  request, spawn another process, schedule a timer, or write, append, create,
  rename, remove, chmod, truncate, or delete any path.
- No endpoint, HTTP response shape, UI route, selector, accessible name, or
  global page-shell text is introduced.

### Link-valid state and error precedence

A link-valid state is a parsed, non-null, non-array JSON object with own
`events`, `jobs`, `approvals`, and `outbox` properties whose values are arrays.
Additional top-level properties are allowed and ignored.

Every `events` element must be a non-null, non-array object with an own,
nonempty string `id`. Event IDs must be pairwise distinct. Other event
properties are opaque.

Every `jobs` element must be a non-null, non-array object with:

- an own, nonempty string `id`, pairwise distinct across jobs;
- an own, nonempty string `eventId` equal to exactly one stored event `id`,
  with no two jobs sharing one `eventId`; and
- an own string `status` equal to exactly `pending`, `done`, or `dead`.

Other job properties are opaque. Event records need not have a related job.
Entries in `approvals` and `outbox` are wholly opaque because this command
does not consume them. The command validates all events, jobs, ID uniqueness,
and links before searching for `<job-id>`.

After arity validation, failures have this exact precedence:

1. A nonexistent path, non-file path, or any filesystem read failure exits
   `1`, writes zero bytes to stdout, and writes exactly
   `job-link: state file is unreadable\n` to stderr.
2. Readable bytes rejected by `JSON.parse` exit `1`, write zero bytes to
   stdout, and write exactly
   `job-link: state file is not valid JSON\n` to stderr.
3. Parsed JSON that is not link-valid exits `1`, writes zero bytes to stdout,
   and writes exactly
   `job-link: state file has invalid Relay state\n` to stderr.
4. Only link-valid state reaches exact-ID lookup and the frozen not-found or
   success result.

Every error is one fixed LF-terminated line. No error includes the state path,
supplied ID, operating-system error, parser text, input bytes, stack trace,
event payload, job error, approval action or reason, outbox content, or other
state content.
