## Description

Add a zero-dependency, read-only CommonJS command that counts persisted Relay
outbox entries whose referenced approval has a supplied exact status while
Relay is offline.

## Acceptance criteria

1. `node app/tools/outbox-approval-status-count.js <state-file> <approval-status>`
   emits compact JSON containing exactly one `outboxEntriesForApprovalStatus`
   integer.
2. Status matching is exact and case-sensitive. Every outbox entry must
   reference exactly one valid approval; duplicate approval IDs and missing
   references are rejected before counting, and zero matches is valid.
3. Invalid arguments are rejected before file access. Unreadable, malformed,
   or structurally invalid state returns fixed redacted errors.
4. The command is offline, zero-dependency, deterministic, read-only, and
   self-terminating. Tests resolve fixtures from the test file, work from any
   current directory, use a five-second child timeout, and do not assume Git
   history depth.
5. Tests precede implementation. Targeted, full app, and immutability checks
   pass without dependency, server, schema, manifest, or Factory changes.

### Command interface

`node app/tools/outbox-approval-status-count.js <state-file> <approval-status>`

- Exactly 2 positional arguments are required. 0, 1, 3, or more arguments
  produce the usage error below, exit code `2`, before any filesystem access
  (`fs.readFileSync` is never called).
- Usage error, exit `2`, empty stdout:
  `usage: node app/tools/outbox-approval-status-count.js <state-file> <approval-status>\n`
- Success: exit `0`, empty stderr, stdout is exactly
  `{"outboxEntriesForApprovalStatus":<N>}\n` (compact JSON, this exact single
  key, `<N>` a non-negative JSON integer, no trailing/extra whitespace beyond
  the final `\n`).
- Read failure (absent path, directory path, permission denied, or any other
  `readFileSync` error), exit `1`, empty stdout:
  `outbox-approval-status-count: cannot read state file\n`
- JSON parse failure, exit `1`, empty stdout:
  `outbox-approval-status-count: state file is not valid JSON\n`
- Structurally invalid Relay state (see below), exit `1`, empty stdout:
  `outbox-approval-status-count: invalid Relay state\n`
- Read-only: the command never creates, writes, or modifies any filesystem
  path. Repeated invocations against the same fixture leave its bytes and
  `fs.statSync(..., { bigint: true })` `mode`/`size`/`mtimeNs` unchanged, and
  leave the parent directory's entry list unchanged.
- Zero-dependency/offline/deterministic/self-terminating: the file's only
  `require` specifier is `"node:fs"`, its only `node:fs` operation is
  `readFileSync`, and it contains none of the literal substrings `server.js`,
  `fetch(`, `WebSocket`, `node:http`, `node:https`, `node:net`,
  `node:child_process`, `setTimeout`, `setInterval`.

### State validation (`isValidState`)

`state` is valid iff all of:

1. `state` is a non-null, non-array object.
2. `state.events`, `state.jobs`, `state.approvals`, `state.outbox` are each
   an own property and each an array. Other top-level keys (e.g.
   `metadata`) may be present and are ignored.
3. Every element of `state.approvals` is a non-null, non-array object with:
   `id` a non-empty string, `jobId` a non-empty string, `status` a string
   that is one of `"pending"`, `"sent"`, `"rejected"`,
   `"blocked_recipient"`. No two elements of `state.approvals` share the
   same `id`.
4. Every element of `state.outbox` is a non-null, non-array object with own
   properties `to`, `subject`, `body` present (any type), `approvalId` a
   non-empty string, and `sentAt` a non-empty string. No two elements of
   `state.outbox` share the same `approvalId`.
5. Every `state.outbox[i].approvalId` equals the `id` of some element of
   `state.approvals` (rules 3–4 guarantee at most one match, so this is
   "exactly one valid approval" per outbox entry). Any outbox entry whose
   `approvalId` matches no approval makes the whole state invalid.

`state.jobs` and `state.events` element contents are not otherwise
validated. Any violation of 1–5 makes the state invalid.

### Count semantics

`outboxEntriesForApprovalStatus` is the number of `state.outbox` entries
whose referenced approval (via rule 5) has `status === <approval-status>`
(the second positional argument), compared with exact, case-sensitive `===`
string equality. Zero matches is a successful result (exit `0`), not an
error.
