## Spec'd description

Add `app/tools/outbox-subject-timestamp-count.js`, a zero-dependency CommonJS
command that reads one persisted Relay state file while Relay is offline,
validates the complete sandbox-outbox collection, and counts receipts whose
stored `subject` and `sentAt` values are both strictly equal to two non-empty
operator-supplied strings. It emits only
`{"outboxWithSubjectAndTimestamp":<count>}`, giving operators a precise
receipt-reconciliation diagnostic without starting Relay, changing durable
state, creating a receipt, performing a send, or exposing a supplied filter,
recipient, body, approval ID, event, job, approval, or unrelated state value.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/outbox-subject-timestamp-count.js <state-file> <subject> <sent-at>`.
- Exactly three user-supplied positional arguments are required, and both
  `<subject>` and `<sent-at>` must have JavaScript string length greater than
  zero. Any other arity or a zero-length filter exits `2`, writes zero stdout
  bytes, writes exactly the following single LF-terminated line to stderr,
  and does not read or create a candidate state path:

  ```text
  usage: node app/tools/outbox-subject-timestamp-count.js <state-file> <subject> <sent-at>
  ```

- Whitespace-only filter strings are non-empty and accepted without trimming.
- After argument validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure, including an absent path, a
  directory in place of a regular file, or an OS read denial, exits `1`,
  writes zero stdout bytes, and writes exactly:

  ```text
  outbox-subject-timestamp-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  outbox-subject-timestamp-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  outbox-subject-timestamp-count: invalid Relay state
  ```

- Failure precedence is argument count, non-empty-filter validation, file
  read, JSON parse, complete structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes
  the state path, supplied subject, supplied timestamp, OS error, parser text,
  input bytes, stack trace, recipient, stored subject, body, approval ID,
  stored timestamp, event field, job field, approval field, or second line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable
  simulation of OS permission denial are outside the required fixture matrix;
  if `readFileSync` throws for either, the frozen read-error result applies.
  For the directory fixture, the observable is the exact command envelope,
  not an errno, error class, or operating-system message.

### Structurally valid state, exact matching, and successful output

A structurally valid state for this command is a parsed non-null, non-array
JSON object with own `events`, `jobs`, `approvals`, and `outbox` properties
whose values are arrays. Additional top-level properties are allowed and
ignored.

Every `outbox` element must be a non-null, non-array object with:

- own `to`, `subject`, and `body` properties, whose values are opaque;
- a non-empty string own `approvalId` property; and
- a non-empty string own `sentAt` property.

Outbox `approvalId` values must be pairwise distinct across the complete array.
Additional outbox properties are allowed and ignored. Event, job, and approval
elements are wholly opaque; only the fact that their top-level collections are
arrays is validated. An outbox `approvalId` need not resolve to a stored
approval. No relationship is imposed among receipt fields beyond each field's
individual rule.

The command validates the complete outbox array and approval-ID uniqueness
before counting. A receipt contributes one exactly when both
`receipt.subject === suppliedSubject` and
`receipt.sentAt === suppliedSentAt` are true. Equality is case-sensitive and
performs no trimming, parsing, Unicode normalization, coercion, or
timezone conversion. Because command-line arguments are strings, an opaque
non-string stored `subject` never matches. Stored `sentAt` must already be a
non-empty string but need not parse as a date. Two strings denoting the same
instant in different timezone representations do not match. A valid non-empty
filter pair with no match is a successful query with count zero; there is no
not-found error.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key, in this order, is:

```json
{"outboxWithSubjectAndTimestamp":<nonnegative integer count>}
```

The count is the number of receipts in the validated `outbox` array for which
both exact comparisons succeed. Neither supplied filter is echoed. No stored
recipient, subject, body, approval ID, send timestamp, additional receipt
field, event, job, approval, or top-level metadata value is emitted.
