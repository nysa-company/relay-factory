## Spec'd description

Add `app/tools/outbox-approval-count.js`, a zero-dependency CommonJS command
that reads one persisted Relay state file while Relay is offline, validates the
complete stored sandbox-outbox collection, and counts receipts whose stored
`approvalId` is strictly equal to one operator-supplied `<approval-id>`. It
reports only `{"outboxEntries":<count>}`, allowing an operator to inspect an
approval ID's outbox cardinality without starting Relay, changing durable
state, looking up or echoing a stored approval, creating a receipt, performing
a real send, or exposing the supplied ID, stored IDs, recipients, subjects,
bodies, send timestamps, events, jobs, approvals, or unrelated state.

Product-doc and repository sources:

- [`SPEC.md` behavior 4](../../SPEC.md#behavior-spec) defines approval as the
  operation that creates one allowlisted sandbox outbox record and defines the
  blocked-recipient outcome as creating no send.

  `node app/tools/outbox-approval-count.js <state-file> <approval-id>`.

  ```text

  `1`, writes zero stdout bytes, and writes exactly:

  ```

- Failure precedence is argument count, file read, JSON parse, complete
  structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes

### Structurally valid state, exact match, and successful output

A structurally valid state for this command is a parsed non-null, non-array
JSON object with own `events`, `jobs`, `approvals`, and `outbox` properties
whose values are arrays. Additional top-level properties are allowed and
ignored.

Every `outbox` element must be a non-null, non-array object with:

- own `to`, `subject`, and `body` properties, whose values are opaque;
- a non-empty string own `approvalId` property; and
- a non-empty string own `sentAt` property.

Outbox `approvalId` values must be pairwise distinct across the complete array.
Additional outbox properties are allowed and ignored. Event, job, and approval
elements are wholly opaque; only the fact that their top-level collections are
arrays is validated. An outbox `approvalId` need not resolve to a stored
approval. No relationship is imposed among `to`, `subject`, `body`,
`approvalId`, and `sentAt` beyond each field's individual rule.

The command validates the complete outbox array and approval-ID uniqueness
before counting. A receipt contributes one to the count only when its stored
`approvalId` is strictly equal to the supplied `<approval-id>` using
case-sensitive JavaScript equality. Neither value is trimmed, case-folded,
decoded, prefixed, or normalized. The empty string is an accepted positional
argument but cannot equal any structurally valid non-empty stored
`approvalId`. A supplied ID with no match is a successful query with count
zero; there is no approval lookup and no not-found error.

Because a structurally valid outbox has pairwise-distinct approval IDs, the
only successful counts are `0` and `1`. Success exits `0`, writes zero stderr
bytes, and writes one compact JSON object followed by exactly one LF. Its only
key is:

```json
{"outboxEntries":<0-or-1>}
```

`outboxEntries` is the number of elements in the validated `outbox` array
whose stored `approvalId` matches the supplied ID exactly. The supplied ID is
not echoed. No stored approval ID, recipient, subject, body, send timestamp,
additional outbox field, event, job, approval, or top-level metadata value is
emitted.
