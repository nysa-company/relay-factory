## Spec'd description

Add `app/tools/event-id-type-count.js`, a zero-dependency CommonJS command that
reads one persisted Relay state file while Relay is offline, validates the
complete event collection, and counts events for which both the stored `id`
and stored `type` strictly equal the two non-empty operator-supplied filters.
It emits only `{"eventsWithIdAndType":<count>}`, allowing an operator to make a
narrow conjunction query without starting Relay, changing durable state, or
exposing either filter, event payloads, timestamps, sibling collections, or
other stored content.

Product-doc and repository sources:

- [`SPEC.md` behavior 1](../../SPEC.md#behavior-spec) defines accepted events as
  `{id, type, payload}` and defines idempotency by event ID.
- [`SPEC.md` behaviors 6 and 7](../../SPEC.md#behavior-spec) make the atomically
  persisted file Relay's durable state and make events operator-visible.
- [`SPEC.md` conformance cases 1, 2, and 7](../../SPEC.md#test-cases-the-conformance-suite)
  require accepted events to remain visible, duplicate event IDs not to create
  duplicate work, and persisted work to survive restart.
- The current [`app/server.js` state model](../../app/server.js) establishes the
  four stored collections and persists accepted events with `id`, `type`,
  `payload`, and `receivedAt`.
- The shipped [`event-count` command](../../app/tools/event-count.js) and its
  [acceptance suite](../../app/tests/event-count.test.js) establish complete
  event validation, unique event IDs, compact count-only output, redacted
  failures, and the read-only offline convention.
- The shipped
  [`event-type-count` command](../../app/tools/event-type-count.js) and its
  [acceptance suite](../../app/tests/event-type-count.test.js) establish exact
  case-sensitive event-field matching and successful zero-match queries.
- [`AGENTS.md` Boundaries](../../AGENTS.md#boundaries) keeps `app/`
  zero-dependency, while [`AGENTS.md` Verification](../../AGENTS.md#verification)
  and the managed repository baseline define later implementation checks.

No endpoint, HTTP shape, UI selector, global-shell UI text, persisted schema,
server behavior, package, dependency, lockfile, manifest, Factory control,
authentication path, deployment topology, or external-send behavior changes.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/event-id-type-count.js <state-file> <event-id> <type>`.
- Exactly three user-supplied positional arguments are required, and both
  `<event-id>` and `<type>` must have JavaScript string length greater than
  zero. Wrong arity or either empty filter exits `2`, writes zero stdout bytes,
  writes exactly the following single LF-terminated line to stderr, and does
  not read or create the candidate state path:

  ```text
  usage: node app/tools/event-id-type-count.js <state-file> <event-id> <type>
  ```

- Filter validation checks only exact string length. A filter containing only
  whitespace is non-empty and valid. Command-line arguments are already
  strings; the command does not trim, parse, coerce, decode, case-fold, or
  Unicode-normalize them.
- After argument validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure, including an absent path, a
  directory in place of a regular file, or OS read denial, exits `1`, writes
  zero stdout bytes, and writes exactly:

  ```text
  event-id-type-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  event-id-type-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  event-id-type-count: invalid Relay state
  ```

- Failure precedence is argument count, non-empty event-ID and type filters,
  file read, JSON parse, complete structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes
  the state path, either supplied filter, OS error, parser text, input bytes,
  stack trace, stored field, payload, sibling collection value, or second line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable
  simulation of OS permission denial are outside the required fixture matrix;
  if `readFileSync` throws for either, the frozen read-error result applies.
  The directory fixture freezes the command envelope, not an errno, error
  class, or operating-system message.

### Structurally valid state, conjunction, and successful output

A structurally valid state is a parsed non-null, non-array JSON object with own
`events`, `jobs`, `approvals`, and `outbox` properties whose values are arrays.
Additional top-level properties are allowed and ignored.

Every `events` element must be a non-null, non-array object with non-empty
string own properties `id`, `type`, and `receivedAt`. Event IDs must be
pairwise distinct across the complete array. Event `payload` and all
additional event fields are opaque. Job, approval, and outbox elements are
wholly opaque; only the fact that their top-level collections are arrays is
validated.

The command validates the complete event array and ID uniqueness before
counting. An event contributes one only when both
`event.id === <event-id>` and `event.type === <type>` using JavaScript strict
string equality. It performs no trimming, parsing, coercion, decoding, case
folding, or Unicode normalization of stored or supplied values. A valid query
with no conjunctive match succeeds with count zero; there is no not-found
error. Because valid stored event IDs are unique, the count is always `0` or
`1` for structurally valid state.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key is:

```json
{"eventsWithIdAndType":<integer 0 or 1>}
```

The value is the number of validated events satisfying both comparisons. No
supplied filter, stored event field, payload, additional event field, job,
approval, outbox, or top-level metadata value is emitted.
