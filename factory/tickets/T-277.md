## Description

Relay creates one job per accepted event, but the offline `job-progress`
report accepts two jobs that reference the same event ID. Reject duplicate
non-empty job `eventId` values before lookup or reporting.

## Acceptance criteria

1. A state containing two otherwise valid jobs with the same non-empty
   `eventId` exits `1`, writes exactly the existing invalid-state stderr line,
   and writes zero stdout bytes.
2. Duplicate event IDs are invalid whether the requested job is first,
   second, or absent and whether the jobs have different statuses. Complete
   job validation and uniqueness checking precede lookup.
3. Valid jobs with unique event IDs retain the existing output shape, field
   order, exact lookup, exit statuses, and stderr messages byte-for-byte.
4. Existing collection, job-field, status, counter, last-error, and unique job
   ID validation remain unchanged. Event records are not made unique here.
5. Failures remain redacted and leak no job or event ID, error text, state
   bytes, input path, parser detail, or operating-system detail.
6. The command remains offline, zero-dependency, deterministic, read-only, and
   self-terminating. Tests precede implementation; the targeted test, full app
   suite, and immutability check pass without other product or Factory changes.
