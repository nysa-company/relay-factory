## Spec'd description

Add `app/tools/outbox-body-count.js`, a zero-dependency CommonJS command that
reads one persisted Relay state file while Relay is offline, validates the
complete sandbox-outbox collection, and counts receipts whose stored `body`
value is strictly equal to one operator-supplied `<body>` string. It reports
only `{"outboxEntriesWithBody":<count>}`, so an operator can inspect body
cardinality without starting Relay, changing durable state, creating a
receipt, performing a real send, or exposing supplied or stored content.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/outbox-body-count.js <state-file> <body>`.
- Exactly two user-supplied positional arguments are accepted. Any other
  arity exits `2`, writes zero stdout bytes, writes exactly the following
  single LF-terminated line to stderr, and does not read or create a candidate
  state path:

  ```text
  usage: node app/tools/outbox-body-count.js <state-file> <body>
  ```

- After arity validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure, including an absent path, a
  directory in place of a regular file, or an OS read denial, exits `1`,
  writes zero stdout bytes, and writes exactly:

  ```text
  outbox-body-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  outbox-body-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  outbox-body-count: invalid Relay state
  ```

- Failure precedence is argument count, file read, JSON parse, complete
  structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error
  includes the state path, supplied body, OS error, parser text, input bytes,
  stack trace, outbox field, event field, job field, approval field, or second
  line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable
  simulation of OS permission denial are outside the required fixture matrix;
  if `readFileSync` throws for either, the frozen read-error result applies.

### Structurally valid state, exact match, and successful output

A structurally valid state is a parsed non-null, non-array JSON object with
own `events`, `jobs`, `approvals`, and `outbox` properties whose values are
arrays. Additional top-level properties are allowed and ignored.

Every `outbox` element must be a non-null, non-array object with:

- own `to`, `subject`, and `body` properties, whose values are opaque;
- a non-empty string own `approvalId` property; and
- a non-empty string own `sentAt` property.

Outbox `approvalId` values must be pairwise distinct across the complete
array. Additional outbox properties are allowed and ignored. Event, job, and
approval elements are wholly opaque; only their top-level collections being
arrays is validated. An outbox `approvalId` need not resolve to an approval.
No relationship is imposed among the five receipt fields beyond their
individual rules.

The command validates the complete outbox array and approval-ID uniqueness
before counting. A receipt contributes one only when its stored `body` value
is strictly equal to the supplied `<body>` using case-sensitive JavaScript
equality. It does not trim, parse, coerce, case-fold, decode, or
Unicode-normalize either value. Since CLI arguments are strings, an opaque
non-string stored body never matches. Empty and unknown body arguments are
valid queries and return zero when unmatched; there is no not-found error.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key is:

```json
{"outboxEntriesWithBody":<nonnegative integer count>}
```

The count is the number of validated outbox elements whose stored `body`
matches the supplied argument exactly. The argument is not echoed. No stored
body, recipient, subject, approval ID, send timestamp, additional outbox
field, event, job, approval, or metadata value is emitted.
