## Description

Relay can list dead jobs or inspect one known job, but operators cannot obtain
a compact offline list of work still pending. Add the matching pending-job
diagnostic without exposing stored errors or event payloads.

## Acceptance criteria

1. `node app/tools/pending-jobs.js <state-file>` exits `0`, writes one compact
   JSON array line, and writes zero stderr bytes for valid state.
2. The array contains only pending jobs, sorted by job ID in code-point order.
   Each entry has exactly `id`, `eventId`, `attempts`, and `retries` in that
   order. Empty or all-non-pending jobs emit `[]`.
3. Job records require unique non-empty IDs and event IDs, a supported status,
   non-negative integer attempts, retries, and attempts-since-retry, and a
   null-or-string last error. Invalid records fail before filtering.
4. Usage, unreadable-file, invalid-JSON, and invalid-state failures use fixed
   redacted one-line stderr messages, the established exit codes, and zero
   stdout bytes. No errors, payloads, state contents, or paths leak.
5. Repeated invocation is byte-for-byte deterministic. The command is offline,
   zero-dependency, read-only, and self-terminating, and changes no input bytes,
   metadata, or sibling paths.
6. Tests precede implementation; the targeted test, full app suite, and
   immutability check pass without other product or Factory changes.
