## Description

The existing status-count command answers one job-status query at a time. Add
a dedicated offline command that reports the complete pending, done, and dead
job breakdown in one stable result.

## Acceptance criteria

1. `node app/tools/job-status-summary.js <state-file>` exits `0`, writes exactly
   one compact JSON line shaped as
   `{"jobs":{"pending":N,"done":N,"dead":N}}`, and writes zero stderr bytes
   for valid state.
2. Every job is counted exactly once under its stored status. Empty jobs emit
   all three keys with zero values, in the specified order.
3. Job records require unique non-empty IDs and event IDs, a supported status,
   non-negative integer attempts, retries, and attempts-since-retry, and a
   null-or-string last error. Invalid records fail before counting.
4. Usage, unreadable-file, invalid-JSON, and invalid-state failures use fixed
   redacted one-line stderr messages, the established exit codes, and zero
   stdout bytes. No IDs, errors, state contents, or paths leak.
5. Repeated invocation is byte-for-byte deterministic. The command is offline,
   zero-dependency, read-only, and self-terminating, and changes no input bytes,
   metadata, or sibling paths.
6. Tests precede implementation; the targeted test, full app suite, and
   immutability check pass without other product or Factory changes.
