## Spec'd description

Add `app/tools/approval-recipient-body-count.js`, a zero-dependency CommonJS
command that reads one persisted Relay state file while Relay is offline,
validates the complete approval collection, and counts approvals for which the
stored `action.to` and `action.body` values both exactly equal two supplied
command-line strings. It emits only
`{"approvalsWithRecipientAndBody":<count>}` so an operator can inspect the
conjunction without starting Relay, changing state, approving or rejecting an
action, creating an outbox receipt, performing a send, or exposing supplied or
stored message data.

  `node app/tools/approval-recipient-body-count.js <state-file> <recipient> <body>`.
- Exactly three user-supplied positional arguments are accepted. Any other

  ```text
  usage: node app/tools/approval-recipient-body-count.js <state-file> <recipient> <body>
  ```

  UTF-8. Any `readFileSync` failure exits `1`, writes zero stdout bytes, and


  ```text

  ```

- A parsed value failing the structural rules exits `1`, writes zero stdout
  bytes, and writes:

  ```text
  approval-recipient-body-count: invalid Relay state
  ```

- Precedence is arity, read, parse, complete structural validation, then
  counting. Every error is one fixed line with exactly one LF and includes no
  path, supplied argument, OS error, parser text, input byte, stack trace,
  stored field, or second line.
- Acceptance uses absolute temporary paths. Symlinks and portable simulation
  of permission denial are outside the fixture matrix; if `readFileSync`
  throws, the read-error result applies.

### Valid state, conjunction, and success shape

A valid state is a parsed non-null, non-array object with own `events`, `jobs`,
`approvals`, and `outbox` array properties. Extra top-level properties are
allowed and ignored. Every approval is a non-null, non-array object with:

- non-empty string own `id`, `jobId`, and `proposedAt` properties;
- own `status` exactly `pending`, `sent`, `rejected`, or
  `blocked_recipient`;
- own non-null, non-array object `action` with own `to`, `subject`, and `body`
  properties; and
- absent `reason`, or own `reason` equal to `null` or any string, including
  `""` and `" "`.

Approval IDs are pairwise distinct across the complete array. Action values
are opaque; extra action and approval fields are ignored. Event, job, and
outbox elements are opaque beyond their collection arrays. A `jobId` need not
resolve, timestamps need not parse, and no cross-field relationship is
imposed.

After validating the whole approval array and ID uniqueness, an approval
contributes exactly once only when both
`approval.action.to === <recipient>` and
`approval.action.body === <body>` using case-sensitive JavaScript strict
equality. Neither operand is coerced, trimmed, case-folded, decoded, or
Unicode-normalized. CLI values are strings, so non-string stored values never
match. Empty recipient and body strings are valid arguments. Zero matches is
a successful query.

Success exits `0`, writes zero stderr bytes, and writes exactly one compact
JSON object followed by one LF. Its only key is:

```json
{"approvalsWithRecipientAndBody":<nonnegative integer count>}
```

Neither supplied argument nor any stored action, approval, event, job, outbox,
or metadata value is emitted.
