## Spec'd description

Add `app/tools/event-id-timestamp-count.js`, a zero-dependency CommonJS
command that reads one persisted Relay state file while Relay is offline,
validates the complete stored event collection, and counts events for which
both the stored `id` and stored `receivedAt` strictly equal two non-empty
operator-supplied filters. It emits only
`{"eventsWithIdAndTimestamp":<count>}`, allowing an operator to make a narrow
conjunction query without starting Relay, changing durable state, parsing or
normalizing timestamps, or exposing filters, payloads, sibling collections,
or other stored content.

Product-doc and repository sources:

- [`SPEC.md` behavior 1](../../SPEC.md#behavior-spec) defines accepted events
  as `{id, type, payload}` and idempotency by event ID.
- [`SPEC.md` behaviors 6 and 7](../../SPEC.md#behavior-spec) make the atomically
  persisted file Relay's durable state and make events operator-visible.
- [`SPEC.md` conformance cases 1, 2, and 7](../../SPEC.md#test-cases-the-conformance-suite)
  require accepted events to remain visible, duplicate IDs not to duplicate
  work, and persisted work to survive restart.
- The current [`app/server.js` state model](../../app/server.js) establishes
  the four collections and persists events with `id`, `type`, `payload`, and
  an ISO-formatted `receivedAt` string.
- The shipped [`event-count` command](../../app/tools/event-count.js) and its
  [acceptance suite](../../app/tests/event-count.test.js) establish complete
  event validation, unique IDs, compact count-only output, redacted failures,
  and the read-only offline convention.
- The shipped [`event-timestamp` command](../../app/tools/event-timestamp.js)
  and its [acceptance suite](../../app/tests/event-timestamp.test.js) establish
  that `receivedAt` strings are handled verbatim rather than parsed,
  normalized, reformatted, or timezone-converted.
- [`AGENTS.md` Boundaries](../../AGENTS.md#boundaries) keeps `app/`
  zero-dependency; [`AGENTS.md` Verification](../../AGENTS.md#verification)
  and the managed baseline define later implementation checks.

No endpoint, HTTP shape, UI selector, global-shell UI text, persisted schema,

authentication path, deployment topology, or external-send behavior changes.

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/event-id-timestamp-count.js <state-file> <event-id> <timestamp>`.
- Exactly three user-supplied positional arguments are required, and both
  filters must have JavaScript string length greater than zero. Wrong arity or
  an empty filter exits `2`, writes zero stdout bytes, writes exactly this
  single LF-terminated line to stderr, and does not read or create the path:

  ```text
  usage: node app/tools/event-id-timestamp-count.js <state-file> <event-id> <timestamp>
  ```

- Filter validation checks only exact string length. Arguments are already
  strings and are not trimmed, parsed, coerced, decoded, case-folded,
  Unicode-normalized, reformatted, or timezone-converted.
- The command then synchronously reads `<state-file>` as UTF-8. Any
  `readFileSync` failure exits `1`, writes zero stdout bytes, and writes:

  ```text
  event-id-timestamp-count: cannot read state file
  ```

- Bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes, and write:

  ```text
  event-id-timestamp-count: state file is not valid JSON
  ```

- A parsed value failing the frozen structure exits `1`, writes zero stdout
  bytes, and writes:

  ```text
  event-id-timestamp-count: invalid Relay state
  ```

- Precedence is argument count, non-empty event ID, non-empty timestamp, file
  read, JSON parse, complete structural validation, then counting.
- Every error is exactly one LF-terminated line. It includes no path, filter,
  OS or parser detail, input byte, stack trace, stored field, payload, sibling
  value, or second line.
- Absolute temporary paths are used. Symlinks and portable permission-denial
  simulation are outside the fixture matrix; if `readFileSync` throws, the
  frozen read error applies. The directory case freezes the envelope, not an
  OS-specific errno or error class.

### Structurally valid state, conjunction, and successful output

A valid state is a parsed non-null, non-array JSON object with own `events`,
`jobs`, `approvals`, and `outbox` array properties. Additional top-level
properties are allowed and ignored.

Every event must be a non-null, non-array object with non-empty string own
properties `id`, `type`, and `receivedAt`. Event IDs are pairwise distinct
across the complete array. `payload` and extra event fields are opaque. Job,
approval, and outbox elements are wholly opaque; only their collections being
arrays is validated. `receivedAt` values need not be distinct or parseable.

The complete event array and ID uniqueness are validated before counting. An
event contributes one only when both `event.id === <event-id>` and
`event.receivedAt === <timestamp>` by JavaScript strict string equality on the
same event. No trimming, parsing, coercion, decoding, case folding, Unicode
normalization, reformatting, or timezone conversion occurs. No match succeeds
with count zero. Unique IDs bound every valid result to `0` or `1`.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
plus exactly one LF, with no other key:

```json
{"eventsWithIdAndTimestamp":<integer 0 or 1>}
```

No filter, stored event field, payload, extra event field, sibling collection,
or top-level metadata value is emitted.
