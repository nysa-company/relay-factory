## Description

Relay can persist the numeric event type `7`, but the offline
`event-type-count` command rejects the whole state before it can count an
unrelated string type. One legitimate numeric sibling therefore prevents an
operator from querying ordinary string event types.

Accept persisted non-zero JSON-number types during structural validation.
Keep the command-line query a literal string and preserve strict,
non-coercing matching: query text `7` must not match stored number `7`.

## Acceptance criteria

1. Given a valid state containing events with stored types `7`, `-0.5`, and
   `meeting`, querying `meeting` exits `0`, writes the existing compact JSON
   result with count `1`, and writes zero stderr bytes.
2. Querying the same state with literal argument `7` or `-0.5` exits `0` and
   reports count `0`. The command does not parse JSON arguments, coerce values,
   or change case-sensitive string equality.
3. Existing valid all-string states and outputs remain byte-for-byte
   unchanged. Missing or empty types, zero, booleans, objects, arrays, invalid
   IDs or timestamps, and duplicate event IDs remain invalid.
4. Failures retain the existing exit codes, fixed redacted one-line messages,
   validation precedence, and zero stdout bytes.
5. The command remains deterministic, offline, zero-dependency, read-only,
   and self-terminating. It changes no input bytes, metadata, or sibling path.
6. Tests precede implementation. The targeted test, full app suite, and
   immutability check pass without server, schema, package, dependency,
   Factory, route, or configuration changes.
