## Description

Add a zero-dependency, read-only Node command that counts persisted Relay jobs
whose status and retry count exactly match operator-supplied values. This lets
operators distinguish retry histories within one queue state without starting
Relay or exposing job contents.

## Acceptance criteria

1. `node app/tools/job-status-retry-count.js <state-file> <status> <retries>`
   emits compact JSON containing exactly one `jobsWithStatusAndRetries` integer.
2. Status must be exactly `pending`, `done`, or `dead`; retries must be a
   canonical non-negative integer. Both filters must match each counted job.
3. Invalid arguments are rejected before file access. Unreadable, malformed,
   or structurally invalid state returns fixed redacted errors; complete job
   validation precedes counting.
4. Every invocation is offline, read-only, deterministic, and self-terminating.
5. Tests precede implementation. Targeted, full app, and immutability checks
   pass without dependency, server, schema, manifest, or Factory changes.
