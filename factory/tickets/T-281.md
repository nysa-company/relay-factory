## Description

Add a zero-dependency, read-only CommonJS command that counts persisted Relay
outbox entries whose recipient exactly matches a supplied value and whose
`body` is a non-empty string while Relay is offline.

This change is derived from the persisted outbox record shape (`to`,
`subject`, `body`, `approvalId`, `sentAt`) in
[`SPEC.md` Behavior spec items 4 and 7](../../SPEC.md#behavior-spec), and
follows the existing offline recipient-count command convention in
`app/tools/outbox-recipient-count.js`. The zero-dependency, read-only, and
verification constraints come from
[`AGENTS.md` Boundaries](../../AGENTS.md#boundaries) and
[`AGENTS.md` Verification](../../AGENTS.md#verification).

## Acceptance criteria

1. `node app/tools/outbox-recipient-body-present-count.js <state-file> <recipient>`
   emits compact JSON containing exactly one
   `outboxEntriesWithRecipientAndTextBody` integer.
2. Recipient matching is exact and case-sensitive, and an entry counts only
   when `body` is a string with `.length > 0`; no value is trimmed, normalized,
   case-folded, or coerced, and zero matches is valid.
3. Invalid arguments are rejected before file access. Unreadable, malformed,
   or structurally invalid state returns fixed redacted errors; complete
   outbox validation precedes filtering and counting.
4. The command is offline, zero-dependency, deterministic, read-only, and
   self-terminating. Tests use a five-second child timeout and prove inputs are
   unchanged.
5. Tests precede implementation. Targeted, full app, and immutability checks
   pass without dependency, server, schema, manifest, or Factory changes.

### CLI interface

- Invocation: `node app/tools/outbox-recipient-body-present-count.js
  <state-file> <recipient>` — exactly two positional arguments, `<state-file>`
  (a path) and `<recipient>` (an opaque string, including the empty string).
- Argument-count check runs before any filesystem access. Any argument count
  other than exactly two is a usage error: stderr is exactly
  `usage: node app/tools/outbox-recipient-body-present-count.js <state-file> <recipient>\n`,
  stdout is empty, and the process exits `2`. The candidate state-file path is
  never touched (not created, read, or stat'd) on this branch.
- File-read failure (path absent, or path is a directory, or otherwise
  unreadable): stderr is exactly
  `outbox-recipient-body-present-count: cannot read state file\n`, stdout is
  empty, exit `1`.
- JSON-parse failure (file content is not valid JSON, including the empty
  file): stderr is exactly
  `outbox-recipient-body-present-count: state file is not valid JSON\n`,
  stdout is empty, exit `1`. No fragment of the unparsable content is echoed
  to stdout or stderr.
- Structural-validity failure (parses as JSON but fails "State validation"
  below): stderr is exactly
  `outbox-recipient-body-present-count: invalid Relay state\n`, stdout is
  empty, exit `1`.
- Success: stdout is exactly one line, compact JSON,
  `{"outboxEntriesWithRecipientAndTextBody":<N>}\n` (single key, `<N>` the
  non-negative integer count below), stderr is empty, exit `0`.
- The command never writes to `<state-file>`, never creates or modifies any
  other file, and performs no network I/O. It reads the file once, computes
  the count, prints, and exits — no timers, no long-lived handles, so the
  process exits on its own without an explicit `process.exit` call forcing
  termination.

### State validation (must pass before counting)

The parsed JSON value `state` is valid only if all of the following hold;
any failure makes the whole state invalid and short-circuits before any
counting:

1. `state` is a non-null object and not an array.
2. `state` has own properties `events`, `jobs`, `approvals`, `outbox`, each an
   `Array` (element contents of `events`, `jobs`, `approvals` are not
   otherwise validated by this command).
3. Every element of `state.outbox` is a non-null object, not an array, with:
   - an own property `to` present (any JSON value type — the value is not
     type-checked at validation time, only at counting time);
   - an own property `subject` present (any JSON value type);
   - an own property `body` present (any JSON value type);
   - an own property `approvalId` whose value is a `string` with
     `.length > 0`;
   - an own property `sentAt` whose value is a `string` with `.length > 0`.
4. No two elements of `state.outbox` share the same `approvalId` string
   (duplicate `approvalId` values invalidate the whole state).

### Counting predicate

For each element `r` of the validated `state.outbox`, `r` counts toward `<N>`
if and only if both hold:

- `r.to === recipient` — JavaScript strict equality against the literal
  second CLI argument. `recipient` is always a string, so any stored `to`
  that is not a string (number, object, array, boolean, null) never matches.
  No trimming, case-folding, or Unicode normalization is applied to either
  side.
- `typeof r.body === "string" && r.body.length > 0` — a present-but-empty
  string, or any non-string `body` (validation only requires the key to be
  present, not that it be a string), does not count.

`<N>` is the number of matching elements; `0` is a valid, successful result
(exit `0` with `{"outboxEntriesWithRecipientAndTextBody":0}\n`), not an
error.
