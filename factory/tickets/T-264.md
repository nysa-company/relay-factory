## Description

Relay persists a truthy numeric event `type` unchanged, and T-190 established
the stored numeric value `7` as legitimate opaque event data. The existing
offline `event-count` command instead rejects that state before counting it.

Make `event-count` accept persisted non-zero JSON-number event types. Preserve
its existing total-count output, string-type behavior, structural checks,
error precedence, privacy boundary, and read-only behavior.

## Acceptance criteria

1. Valid states containing events whose stored `type` values include positive
   integer `7` and negative fraction `-0.5` exit `0`, write exactly the
   existing compact total-count JSON line, and write zero stderr bytes.
2. A mixed state containing string, positive-integer, and negative-fraction
   event types counts every event exactly once. Repeated invocation is
   byte-for-byte deterministic.
3. Existing valid string-type states and their output remain unchanged.
   Missing or empty types, zero, booleans, objects, arrays, invalid IDs or
   timestamps, and duplicate event IDs retain the existing invalid-state
   failure.
4. No event ID, type, payload, timestamp, job error, approval content, outbox
   content, input path, parser detail, or operating-system detail leaks on a
   failure.
5. The command remains offline, zero-dependency, read-only, and
   self-terminating. The state bytes, metadata, and sibling paths remain
   unchanged.
6. Tests precede implementation. The targeted test, full app suite, and
   immutability check pass without server, schema, package, dependency,
   Factory, route, or configuration changes.

## Coordination

This ticket owns only `app/tools/event-count.js` and
`app/tests/event-count.test.js`. It is independent of T-265 and T-266. It
supersedes only the older commands' assumption that every valid event type is
