## Spec'd description

Add `app/tools/outbox-recipient-timestamp-count.js`, a zero-dependency
CommonJS command that reads one persisted Relay state file while Relay is
offline, validates the complete stored sandbox-outbox collection, and counts
receipts whose stored `to` and `sentAt` values are both strictly equal to the
operator-supplied `<recipient>` and `<sent-at>` strings. It reports only
`{"outboxWithRecipientAndTimestamp":<count>}`, so an operator can inspect the
intersection without starting Relay, changing durable state, creating a
receipt, performing a send, or exposing supplied or persisted content.

Product-doc and repository sources:

- [`SPEC.md` behaviors 3 and 4](../../SPEC.md#behavior-spec) define the send
  action's `to` value and the sandbox outbox record created by approval.
- [`SPEC.md` behaviors 6 and 7](../../SPEC.md#behavior-spec) make the persisted
  state file Relay's durable source and the outbox operator-visible, while
  [`SPEC.md` conformance cases 5-7](../../SPEC.md#test-cases-the-conformance-suite)
  require approval gating, allowlist enforcement, and duplicate-free recovery.
- [`SPEC.md`'s known modeling limitation](../../SPEC.md#known-modeling-limitation)

  delivery.
- The current [`app/server.js` state model](../../app/server.js) persists each

### Structurally valid state, exact match, and success

A structurally valid state is a parsed non-null, non-array JSON object with
own `events`, `jobs`, `approvals`, and `outbox` properties whose values are
arrays. Additional top-level properties are allowed and ignored.

Every `outbox` element must be a non-null, non-array object with own `to`,
`subject`, and `body` properties whose values are opaque; a non-empty string
own `approvalId`; and a non-empty string own `sentAt`. Approval IDs must be
pairwise distinct across the complete outbox. Additional receipt properties
are allowed and ignored. Event, job, and approval elements are opaque. An
outbox approval ID need not resolve to a stored approval.

The complete outbox and approval-ID uniqueness are validated before counting.
A receipt contributes one only when `receipt.to === recipient` and
`receipt.sentAt === sentAt`. Matching is case-sensitive and performs no
trimming, parsing, coercion, case folding, or timezone conversion. CLI values
are strings: a numeric stored `to` never equals the
string `"7"`; a stored timestamp string `"7"` can equal query string `"7"`.
The empty recipient is allowed and can match an opaque stored empty `to`; the
empty timestamp is allowed but cannot match a structurally valid non-empty
`sentAt`. No match is successful, not an error.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key is:

```json
{"outboxWithRecipientAndTimestamp":<nonnegative integer count>}
```

No supplied or stored recipient, timestamp, subject, body, approval ID,
additional receipt field, event, job, approval, or metadata value is emitted.
