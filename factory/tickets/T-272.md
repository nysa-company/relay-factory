## Description

Operators can inspect one approval or one subset at a time, but cannot obtain a
small complete status breakdown from a saved Relay state. Add a deterministic
offline command for that diagnostic.

## Acceptance criteria

1. `node app/tools/approval-status-summary.js <state-file>` exits `0`, writes
   exactly one compact JSON line shaped as
   `{"approvals":{"pending":N,"sent":N,"rejected":N,"blocked_recipient":N}}`,
   and writes zero stderr bytes for valid state.
2. Every approval is counted exactly once under its stored status. Empty
   approvals emit all four keys with zero values, in the specified order.
3. Approval records require unique non-empty approval and job IDs and one of
   the four supported statuses. Invalid records fail before counting.
4. Usage, unreadable-file, invalid-JSON, and invalid-state failures use fixed
   redacted one-line stderr messages, the established exit codes, and zero
   stdout bytes. No IDs, recipients, actions, reasons, state contents, or paths
   leak.
5. Repeated invocation is byte-for-byte deterministic. The command is offline,
   zero-dependency, read-only, and self-terminating, and changes no input bytes,
   metadata, or sibling paths.
6. Tests precede implementation; the targeted test, full app suite, and
   immutability check pass without other product or Factory changes.
