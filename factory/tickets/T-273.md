## Description

Relay job IDs are identities, but the offline `dead-jobs` report currently
accepts duplicate IDs and can emit two conflicting rows for one job. Make the
command reject that malformed state before filtering or reporting.

## Acceptance criteria

1. A state containing two otherwise valid jobs with the same non-empty `id`
   exits `1`, writes exactly the existing invalid-state stderr line, and writes
   zero stdout bytes.
2. Duplicate IDs are invalid whether both jobs are dead or one is pending or
   done. Complete job validation and uniqueness checking precede filtering.
3. Valid unique jobs retain the existing output shape, field order, ID sort,
   exit status, and stderr behavior byte-for-byte. An empty or no-dead-job
   state still emits `[]`.
4. Existing structural validation, supported statuses, numeric counter rules,
   and null-or-string error rule remain unchanged. Event IDs are not made
   unique by this ticket.
5. Failures remain redacted and leak no job error, event payload, state bytes,
   input path, parser detail, or operating-system detail.
6. The command remains offline, zero-dependency, deterministic, read-only, and
   self-terminating. Tests precede implementation; the targeted test, full app
   suite, and immutability check pass without other product or Factory changes.
