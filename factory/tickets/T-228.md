## Spec'd description

Add `app/tools/event-payload-number-count.js`, a zero-dependency CommonJS
command that reads one persisted Relay state file while Relay is offline,
validates the complete stored event collection, and counts events having at
least one direct own payload property whose value is a finite JavaScript
number. It reports only `{"eventsWithPayloadNumber":<count>}` so an operator
can inspect numeric-payload cardinality without starting Relay, changing
durable state, enqueueing work, exposing event or sibling-collection content,
or treating nested, inherited, non-number, `NaN`, or infinite values as
matches. One event contributes at most one regardless of how many qualifying
properties it contains.

Product-doc and repository sources:

- [`SPEC.md` behavior 1](../../SPEC.md#behavior-spec) defines accepted events,
  their `{id, type, payload}` intake, and exact-ID idempotency.
- [`SPEC.md` behavior 6](../../SPEC.md#behavior-spec) makes the atomically
  persisted state file Relay's durable source, which this command reads
  without participating in startup or recovery.
- [`SPEC.md` behavior 7](../../SPEC.md#behavior-spec) makes events
  operator-visible, while
  [`SPEC.md` conformance cases 1, 2, and 7](../../SPEC.md#test-cases-the-conformance-suite)

### Command-line interface and failure precedence

- Repository-root invocation is exactly
  `node app/tools/event-payload-number-count.js <state-file>`.
- Exactly one user-supplied positional argument is accepted. Any other arity
  exits `2`, writes zero stdout bytes, writes exactly the following single
  LF-terminated line to stderr, and does not read or create a candidate state
  path:

  ```text
  usage: node app/tools/event-payload-number-count.js <state-file>
  ```

- After arity validation, the command synchronously reads `<state-file>`
  directly as UTF-8. Any `readFileSync` failure, including an absent path, a
  directory in place of a regular file, or an OS read denial, exits `1`,
  writes zero stdout bytes, and writes exactly:

  ```text
  event-payload-number-count: cannot read state file
  ```

- Readable bytes rejected by `JSON.parse` exit `1`, write zero stdout bytes,
  and write exactly:

  ```text
  event-payload-number-count: state file is not valid JSON
  ```

- A parsed value that fails the frozen structurally-valid-state rules exits
  `1`, writes zero stdout bytes, and writes exactly:

  ```text
  event-payload-number-count: invalid Relay state
  ```

- Failure precedence is argument count, file read, JSON parse, complete
  structural validation, then counting.
- Every error is one fixed line terminated by exactly one LF. No error includes
  the state path, OS error, parser text, input bytes, stack trace, event field,
  payload value, job field, approval field, outbox field, or second line.
- Acceptance uses absolute temporary paths. Symlink inputs and portable
  simulation of OS permission denial are outside the required fixture matrix;
  if `readFileSync` throws for either, the frozen read-error result applies.

### Structurally valid state, finite-number predicate, and success

A structurally valid state is a parsed non-null, non-array object with own
`events`, `jobs`, `approvals`, and `outbox` properties whose values are arrays.
Additional top-level properties are allowed and ignored.

Every `events` element must be a non-null, non-array object with non-empty
string own properties `id`, `type`, and `receivedAt`. Event IDs must be
pairwise distinct across the complete array. Event `payload` is optional and
opaque for structural validity, as are all additional event fields. Job,
approval, and outbox elements are wholly opaque; only the fact that their
top-level collections are arrays is validated.

The command validates the complete event array and ID uniqueness before
counting. An event contributes exactly one when its `payload` is a non-null,
non-array object and at least one direct own enumerable string-keyed payload
property has a value for which both `typeof value === "number"` and
`Number.isFinite(value) === true`. It contributes zero otherwise. The command
does not traverse a direct value that is an object or array, inspect inherited
properties, coerce values, parse numeric strings, or count an event more than
once. `0`, negative numbers, and fractional numbers are finite matches;
`NaN`, `Infinity`, and `-Infinity` are not.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
followed by exactly one LF. Its only key is:

```json
{"eventsWithPayloadNumber":<nonnegative integer count>}
```

No stored event ID, type, payload key or value, `receivedAt`, additional event
field, job, approval, outbox, or metadata value is emitted.
