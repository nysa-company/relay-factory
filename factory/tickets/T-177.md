## Spec'd description

Add `app/tools/event-inspect.js`, a zero-dependency Node 18+ command that reads
one persisted Relay state file while the service is offline and selects one
event by exact ID. It emits only the stored event's `id`, `type`, and
`receivedAt`, plus a Boolean `hasJob` derived from the persisted jobs
collection. This gives an operator a deterministic event lookup without
starting Relay, changing state, or exposing event payloads, job details,
approval actions, or outbox contents.

### Command-line interface and errors

- Repository-root invocation is exactly
  `node app/tools/event-inspect.js <state-file> <event-id>`.
- Exactly two positional arguments are accepted. Relative state paths resolve
  from the command process's working directory; acceptance tests use absolute
  temporary paths.
- Zero, one, or three positional arguments produce exit code `2`, empty
  stdout, and exactly this single LF-terminated stderr line:

  ```text
  usage: node app/tools/event-inspect.js <state-file> <event-id>
  ```

- The command reads `<state-file>` directly as UTF-8. Any read failure,
  including an absent path, a directory in place of a file, or an OS read
  denial, produces exit code `1`, empty stdout, and exactly:

  ```text
  event-inspect: cannot read state file
  ```

- Bytes rejected by `JSON.parse` produce exit code `1`, empty stdout, and
  exactly:

  ```text
  event-inspect: state file is not valid JSON
  ```

- A parsed value that fails the frozen structural rules produces exit code
  `1`, empty stdout, and exactly:

  ```text
  event-inspect: invalid Relay state
  ```

- A valid state with no event whose stored `id` is strictly equal to the
  supplied `<event-id>` produces exit code `1`, empty stdout, and exactly:

  ```text
  event-inspect: event not found
  ```

- Validation precedence is argument count, read, JSON parse, complete
  structural validation, then event lookup.
- Errors never contain the state path, event ID, OS error, parser text, input
  bytes, stack trace, payload, job field, approval field, outbox field, or a
  second line. Every displayed error is terminated by exactly one LF.

### Structurally valid state and successful output

For this command, structurally valid state is a non-null, non-array JSON object
with own `events`, `jobs`, `approvals`, and `outbox` properties whose values
are arrays.

Every `events` element must be a non-null, non-array object with non-empty
string own properties `id`, `type`, and `receivedAt`. Event IDs must be
pairwise distinct. `payload` and all other event fields are opaque and are
never copied to output.

Every `jobs` element must be a non-null, non-array object with a non-empty
string own property `eventId`. All other job fields are opaque. Approval and
outbox elements are wholly opaque. Additional top-level properties are
allowed and ignored.

The event lookup uses exact, case-sensitive JavaScript string equality and
does not trim, normalize, decode, or case-fold either ID. For the selected
event, `hasJob` is `true` iff at least one job has `job.eventId` strictly equal
to the selected stored event ID; otherwise it is `false`.

Success exits `0`, writes zero stderr bytes, and writes one compact JSON object
plus exactly one LF. Its only keys, in order, are:

```json
{"id":<stored id>,"type":<stored type>,"receivedAt":<stored receivedAt>,"hasJob":<boolean>}
```

No endpoint, HTTP shape, route, UI selector, or global page-shell text is
introduced.

   and the [`app/server.js` state model](../../app/server.js) link jobs through
   `job.eventId`. Resolved as exact equality with the selected stored event ID;

   text, exit codes, or precedence. No entry in
   [`factory/rulings.md`](../rulings.md) addresses offline event inspection.
   Resolved as strict case-sensitive equality, usage exit `2`, operational

9. **Topology and external effects.** This is an offline local file read with
